# Orbitrack v3.6.0 — Vanilla App Hardening Log

Date: 2026-08-22
Scope: vanilla Electron app (`index.html`, `app.js`, `styles.css`, `desktop/`) — local only.
Predecessor: [local-only-red-edition-refresh.md](local-only-red-edition-refresh.md)

Nothing was committed, pushed, tagged, published, or deployed. No Supabase or Google Drive
mutation. Build artifacts are local (`npm run pack`, which never publishes).

---

## Why

The Red Edition refresh shipped without a pass for bugs or security regressions, and the
verification gate it cited (`npm run verify:vanilla`) only syntax-checked 4 files — so it never saw
most of that diff. An audit of the app found 4 defects introduced by the refresh (one of which
hard-wedged the app), no Content-Security-Policy anywhere, an unguarded remote-URL load path in the
Electron shell, ~640 lines of dead code from the disabled custom titlebar, and an installer that
bundled the project's own security audit and internal LLM prompts.

---

## Bugs fixed

### The app could be permanently wedged by one click on the splash

`#splash` is a full-viewport overlay, and every `pointerdown` set `_splashHoldOpen = true`. Once
held, `hideSplash()` returned early and **nothing ever retried** — the 12 s failsafe in
`bootstrap.js` was gated on `!_splashReady`, which a successful boot had already set to `true`.
`html.splash-lock` never lifted, so the user was left on an opaque black screen. The only escape was
`Esc`, and the hint carrying that instruction was `display: none !important` with no rule
re-enabling it, while `cursor: default` hid the fact that the surface was interactive at all.

- `app.js` — click was first made a *toggle*, then **removed outright** in round two (see below):
  the loader now simply runs to completion.
- `styles.css` — `.splash-hint` is visible again (it carries the Esc affordance).
- `bootstrap.js` — the 12 s failsafe now always force-dismisses, and stays armed deliberately: once
  boot succeeds it is a harmless no-op, but a stuck splash has no other way out.

### The splash hold was racy and leaked a timer onto a removed node

`hideSplash()` scheduled the fade with `setTimeout` and never re-checked `_splashHoldOpen` in the
callback, so clicking during the 3.2 s minimum wait did nothing — the queued timer dismissed anyway.
`Esc` removed the element and the original timer still fired `classList.add`/`remove()` against the
detached node. Fade and removal timers are now tracked in `_splashFadeTimer`/`_splashRemoveTimer`,
cleared before rescheduling, and the callback re-checks the hold state. The splash `keydown`
listener is now removed when the splash is removed.

### Notes search rebuilt a closed drawer and stole keyboard focus

`closeNotesPanel()` never cleared `_notesSearchTimer`, and the drawer stays in the DOM when closed.
Typing in Notes search and closing within 280 ms rebuilt the hidden panel's `innerHTML`, remounted
the editor into it, and **unconditionally** called `focus()` — pulling focus into a hidden input. The
parallel implementation in `app.js` captured `wasFocused` before its `await`; `notes.js` had omitted
that guard, so it also fired when the user clicked from search into the note editor — the exact
focus jump the debounce was added to prevent. Now: the timer is cleared on close, `runNotesSearch()`
bails when the panel is shut, and the focus call is gated on `wasFocused`.

### A pending search render could repaint the old view over a new route

`_searchRenderJobs` timers were never cancelled on navigation. Typing in Projects search and
clicking a nav item within 320 ms let the queued render overwrite the new page while the hash
already pointed elsewhere; the trailing `dirty` re-queue could fire a second time. Each job now
records the route it was scheduled for and bails if the route moved or its input is gone.

### Both debounce pumps turned errors into silent unhandled rejections

`app.js` and `notes.js` used `try/await/finally` with no `catch`, and every caller was a floating
promise. A DB read failing mid-typing produced an `unhandledrejection` with no user-visible error,
no `recordUserIssue` entry, and a half-rendered view. Both now catch, log, and record.

### The hidden splash canvas rendered at full rate through boot

`splash-sphere.js` is hidden by CSS in the Red Edition splash, but `resize()` fell back to viewport
dimensions when the element measured 0×0 — so it allocated a full DPR-scaled backing store and
painted ~1300 particles per frame, invisibly, exactly while `bootstrapDB()`/`init()` needed the CPU.
It now returns early when the canvas has no client rects. `onResize` also checks `running` again.

### Project attachment counts went stale and could double-count

- `app.js` — the project-document upload path refreshed the badge directly but never called
  `bustWorkspaceCache()`, so the Projects list showed the pre-upload count for the 120 s cache
  lifetime. A regression from the new count cache.
- `db.js` — the Drive/local attachment merge deduped on `String(row.id)`, but Drive rows carry
  `wt_files` ids and local rows carry Dexie auto-increment ids, so the id spaces never collide and a
  file present in both indexes was returned twice. Now deduped on file identity.

### Offline sessions trusted a role from localStorage

`applyRoute()` used `isOffline() ? s : await DB.getUser(s.userId)`, so offline the `role` came
straight out of the 30-day remembered-session blob in `localStorage`. `window.DB` is always local
Dexie, which answers offline, so the stored record is now authoritative; only a thrown DB error
falls back to the payload.

### Local Health could contradict itself, and one undefined broke the page

The failed-sync *check* read only `syncStatus.failed` while the displayed number also counted the
queue, so the card could read "Failed: 3" beside "No failed sync jobs / Healthy". `_getSyncStatus()`
proxies to third-party engines and one `undefined` return rejected the whole Diagnostics page, the
Settings→Diagnostics tab and "Copy report". Both fixed; the browser context is no longer labelled
"Desktop sandbox locked".

### Smaller fixes

- Drive sign-in tried up to 8 `signInWithPassword` calls per bootstrap; it now aborts on rate-limit
  and server errors and retries only the pair it just provisioned after a sign-up.
- Three blocking `alert()` calls in `reports-projects.js` now use the app's toast.
- `desktop/updates.js` said "WorkTracker" instead of "Orbitrack".
- Splash hint copy still read "Click the ocean to keep drifting" — from an entirely different theme.
- Removed a dead `window.clipboardData` IE fallback in `notes.js`.

## Security hardening

| Change | Detail |
|---|---|
| **Content-Security-Policy** | There was none anywhere. `desktop/main.js` now stamps one on every `file://` response: `script-src 'self' file:` with no `'unsafe-inline'`/`'unsafe-eval'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`. `connect-src` is limited to Supabase + googleapis, `img-src` to self/data/blob plus the two Drive thumbnail hosts. Dev-server URLs are deliberately skipped so Vite HMR still works. |
| **Inline scripts removed** | The two inline `<script>` blocks in `index.html` moved to `boot-version.js` and `boot-observability.js` so `script-src` can stay at `'self'`. `verify:vanilla` now fails if an inline `<script>` reappears. |
| **Remote-URL load path closed** | `mainWindow.loadURL(WT_REACT_URL)` had no `isDev` guard, so `WT_REACT=1 WT_REACT_DEV=1 WT_REACT_URL=…` was enough to render a remote origin in the main window *with the privileged preload attached*, including `installUpdate()`. Now gated on `isDev` **and** a loopback host check. |
| **Permission handlers** | Neither `setPermissionRequestHandler` nor `setPermissionCheckHandler` existed, so Electron's permissive defaults applied. Now deny-by-default with a small allowlist. |
| **IPC sender validation** | Every `ipcMain.handle` now requires `senderFrame === mainWindow.webContents.mainFrame`. `updater:install` was previously callable from any frame, including the `blob:` PDF-preview iframe. |
| **Honest security status** | `desktop:get-security-status` returned hardcoded `true` literals, so the Local Health "Desktop sandbox locked" indicator was structurally incapable of ever reporting a problem — and it over-claimed signed updates. It now reads `webContents.getLastWebPreferences()`, reports whether the CSP was installed, and states plainly that the build is unsigned. |
| **`openExternal` narrowed** | `http:` dropped from the allowlist; https/mailto only. |
| **Dead privileged surface removed** | With the native frame restored, the `windowControls` bridge and its four IPC handlers were unreachable but still callable. Deleted. |
| **Installer no longer ships internal material** | `build.files` previously packaged `prompt1-3.md` + `prompt-safe-next.md` (internal LLM task prompts), `AUDIT.md` and `WORKPLAN.md` (this app's own weakness inventory), `CURSOR_LLM_REMODEL_BRIEF.md`, 20 files of `docs/` including the Supabase security runbook, all 8 Edge Function sources plus the full RLS/migration set, `supabase/.temp/linked-project.json`, 18 admin `scripts/`, and 684 KB of `orbitrack-react/src` duplicating the built `dist/`. All removed; `!*.local.js` added. No secrets were ever shipped. |
| **`.gitignore`** | `*.db` / `*.sqlite*` added — the 3.1 MB `hola-coder.db` at the repo root was untracked but not ignored, so one `git add -A` would have committed it. |

## Layout: theme and performance invariance (measured)

The refresh left this as an open follow-up: *"Manually compare Black and Normal mode screenshots."*
It was measured instead, by snapshotting `getBoundingClientRect()` for the sidebar, main column,
content box, sticky header, page header, search input, status pills, grid and first card, toggling
the theme, and diffing.

**Before:** switching Black → Normal moved the entire project grid **up by 23px**. Black gave the
search input `min-height: 50px` and the status pills `min-height: 38px`, while Normal inherited
41px / 31px from the base rules; the 23px accumulated in the sticky header. Horizontal geometry was
already invariant — the earlier work had fixed that axis, not this one.

**Fix:** a `Theme-invariant control metrics` block in `styles.css` pins the search input height,
pill height/padding/border-width, the controls gap, and the page-header row height as shared tokens.
The values are Black's existing ones — Black is the default theme, so its appearance is unchanged
and Normal stops drifting. Only geometry is pinned; colours stay per-theme.

**After:** geometry is identical to sub-pixel precision across the toggle, and the round trip
restores exactly. The three performance modes (Full / Balanced / Low Power) were measured the same
way and are also geometry-identical — they change paint only. Note that switching perf mode calls
`await router()`, so there is a brief re-render before the settled state.

**Not a bug:** `#content` reports 40px of `scrollWidth` overhang. That is the sticky header's
intended full-bleed negative margin painting into `.main-content`'s padding. `html`, `body` and
`.main-content` all report zero horizontal overflow, all header content fits inside its own padding,
and `html` is `overflow-x: hidden` — nothing scrolls sideways and nothing is unreachable. Verified
in both collapsed and expanded sidebar states.

## Dead code removed (~700 lines)

- **Custom titlebar** (`frame: true` disabled it): `initDesktopChrome`, `renderDesktopTitlebarStatus`
  (a permanent no-op still called from 4 sites — one of them inside `persistWorkspaceCache`'s quota
  `try/catch`, where a UI call was being swallowed as a storage error), `setTitlebarChip`, the 30 s
  security poll, `updateDesktopWindowState`, `_desktopChromeBound`, the `windowControls` preload
  bridge, 4 IPC handlers, 4 window-event forwarders broadcasting to nobody, `useVanillaApp`, and
  ~190 lines of CSS that a *second* `display: none !important` block existed only to neutralise.
- **Unreachable Support page**: `renderSupportPage()` returned unconditionally on its third line,
  leaving ~56 dead lines including a duplicate copy of the Support panels.
- **Three generations of splash CSS**: `.splash-core-wrap`, `.splash-inner`, `.splash-edition`,
  `.splash-edition-dot`, `.splash-logo-mark`, `.splash-spec-mark` and `.splash-brand` all targeted
  elements no longer in `index.html`; two of them had been *added* by the refresh and immediately
  hidden. The hidden-by-design DOM was removed too.
- **Duplicate changelog**: `renderAboutPage()` carried a second hand-maintained release array that
  had already drifted a release behind. It now derives from `SUPPORT_CHANGELOG`.

Deliberately **not** attempted: any refactor of `app.js` (12.8k lines) or `styles.css` (14.4k
lines). The theme-invariance layer is `!important`-heavy and brittle, but it works, and rewriting it
without a test harness is a bigger risk than the problem.

## Version 3.6.0 and version info

`3.5.11` was hardcoded in 6 tracked files, 31 occurrences being `?v=` cache-busters. Updated:
`package.json`, `package-lock.json`, all `index.html` cache-busters + splash label,
`date-utils.js` fallback, `desktop/preload.js` fallback, and `boot-version.js`.
`orbitrack-react/src-tauri/*` was left alone — separate product.

- **A `3.6.0` changelog entry** was added to `SUPPORT_CHANGELOG`, which is now the single source for
  the Support tab, the What's New modal *and* the About page timeline.
- **What's New now reads from the changelog.** Its seen-key is version-scoped, so every bump
  re-opens it; with hardcoded bullets it reliably showed the *previous* release's notes under the new
  number. It had 3.5.9-era copy in it.
- **The About dialog is wired up.** `showAboutModal()` was fully written, rendered the version, and
  had zero call sites; a `show-about` action existed but redirected to Settings. There is now an
  "About Orbitrack v3.6.0" item in the user menu, and the dialog carries a build-channel line
  ("Local desktop build - not published") so this artifact is identifiable as a local build.
- **`Update-Orbitrack.bat` can no longer downgrade.** It fetched the latest GitHub release and
  installed it with `/S` with no version comparison at all, so it would have replaced a local 3.6.0
  with the published 3.5.11. It now reads the installed `ProductVersion` and refuses anything not
  newer.

### Version drift can no longer happen quietly

`scripts/verify-vanilla-runtime.mjs` now asserts that `package.json`'s version equals the
`date-utils.js` fallback, the `preload.js` fallback, `boot-version.js`'s fallback, the splash label,
*every* app-owned `?v=` cache-buster, and `SUPPORT_CHANGELOG[0].version` — and that `index.html`
contains no inline `<script>`. A partial bump is now a loud failure instead of a hosted build
reporting the old number while the desktop build reports the new one.

`verify:vanilla` also grew from 4 `node --check` targets to **all 22** scripts the app loads, via
`scripts/check-vanilla-syntax.mjs`, which additionally fails if `index.html` references a missing
script or loads one the checker does not cover. `notes.js`, `bootstrap.js`, `splash-sphere.js` and
`db.js` — four of the files the refresh changed — were previously unchecked.

## Round two — UI colour, contrast and behaviour

Follow-up pass after reviewing the running app.

### The loader no longer stops when clicked

Click-to-hold is gone entirely, not just made escapable: the `pointerdown`
handler, the `_splashHoldOpen` state, the held-state hint strings and the
`is-held` / `is-ready-held` CSS are all removed, and the splash cursor is back to
`default`. The loader now runs to completion on its own; `Esc` still skips ahead
once loading finishes, and the 12s failsafe stays as a backstop.

### The loader artwork can no longer break a checkout

`assets/red-edition-loader.gif` is now **staged in git**, so committing includes
it. On top of that, `app.js` removes the `<img>` if the asset is missing or fails
to decode and marks the splash `.splash-no-art`, so a tree without `assets/`
shows clean type on black instead of a broken-image icon. The handler is bound
with `addEventListener` rather than an inline `onerror`, because the CSP forbids
inline handlers.

### Admin overview colours

Three widgets had colours hardcoded for a light background, with no dark-theme
equivalent:

| Widget | Was | Now |
|---|---|---|
| Workspace Pulse tiles | `color-mix(--accent-light 45%, #fff)` — on the dark theme `--accent-light` is translucent white, so this produced washed-out light-mauve slabs | Dark charcoal with a 7% Motorsport-red tint; a light accent tint in the light themes |
| Activity Histogram | A fixed teal `rgba(18,184,134,…)` pushed to 88% alpha with permanent white text — fought every theme accent and was harsh across 30 cells | A heat *tint* (max ~52% alpha) in the theme's own accent — red on dark, green on light — with `var(--text)` and a soft border |
| User Activity bars | Track hardcoded `#eef2f7` (near-white) with a dark grey→black fill: on the dark theme every low value read as a bright white pill, contrast inverted | Subtle track (`rgba(255,255,255,0.055)` dark / `rgba(15,23,42,0.07)` light) with an accent-coloured fill |

All three now read from one token set (`--admin-tile-bg`, `--admin-heat-rgb`,
`--admin-bar-track`, `--admin-bar-from/to`, `--admin-bar-label`) defined per
theme in a single place.

**A variable-scope bug fell out of this.** The first version declared those
tokens on `:root`. A custom property composed with `var()` resolves against the
element it is *declared* on — and the theme palettes are set on `body.theme-*`,
not `html`. So `--admin-bar-from: color-mix(…, var(--green), …)` on `:root`
resolved `--green` to the light-theme default `#111111` and painted near-black
bars in **every** theme, which is why the light theme still looked "too dark"
after the first fix. Moving the declarations to `body` fixed it. A scan of all
70 theme-scoped variables confirms no other `:root` declaration composes one.

### Document toggle invisible in the light themes

`.project-detail-linear .project-panel-launcher` hardcoded a near-black pill
(`rgba(24,24,27,0.94)`) but took its icon colour from `--linear-text`, which
resolves to the *page* text colour — dark in the light themes. Result: a dark
folder icon on a dark pill. The light themes now get a light pill with dark
iconography (measured: `#052e16` on `#ffffff`), and the count bubble's label
follows the accent. Dark themes are unchanged.

### Admin histogram clipping (a real alignment bug)

The admin two-column grid collapsed to one column at a **980px viewport**
breakpoint, which ignores the sidebar. With the sidebar expanded, a ~1100px
window left each track near 300px — narrow enough that the 10-column,
`minmax(24px, 1fr)` histogram was wider than its own panel and `.dash-panel`
clipped the right-hand cells. Two changes: the collapse breakpoint moved to
1240px, and the histogram now uses `minmax(0, 1fr)` with clamped gap/padding/font
so it can never exceed its panel again. Measured at simulated widths down to a
609px content column: `scrollWidth == clientWidth`, no clipping.

### Banner transparency vs power mode

Asked directly: why is the banner *less* transparent at Full power than at
Balanced? Because a backdrop blur averages whatever is behind it and visually
fills the translucency back in — Full was 74% alpha **plus** `blur(16px)`, while
Balanced was 82% alpha with the blur removed, so the un-blurred one read as more
see-through despite being *more* opaque. The tiers are now explicitly monotonic,
verified from computed styles:

| Mode | Alpha | Blur |
|---|---|---|
| Full | 0.50 | `blur(18px) saturate(1.2)` |
| Balanced | 0.88 | none |
| Low Power | 1.00 (opaque) | none |

### Also in this pass

- `Object.keys(...).sort((a, b) => a - b)` relied on implicit string→number
  coercion; now sorts explicitly with `Number()`.
- `app:get-version` is now sender-guarded like the other five IPC handlers, so
  "every `ipcMain.handle` validates its sender" holds with no exceptions.

## Open items, deliberately not addressed

1. **Supabase `wt_anon_all` RLS exposure** (AUD-001 in [app-audit.md](app-audit.md)) — anonymous
   read/write to every `wt_*` table. Needs a staged, tested database migration, not a local
   renderer edit. Still the highest-severity item in this project.
2. **React `auth.ts` credential derivation** (AUD-002) — a reusable password pepper in browser
   source. Needs a privileged server-side flow and an account migration.
3. **Windows code signing** — needs a real certificate. The updater correctly fails closed on
   unsigned updates, and the security status now says so instead of implying otherwise.
4. **`.env` on this workstation** holds a live `SUPABASE_SERVICE_ROLE_KEY`, `GOOGLE_CLIENT_SECRET`
   and `GOOGLE_REFRESH_TOKEN`. Correctly git-ignored and excluded from packaging, but rotating the
   service-role key is cheap insurance.
5. **`assets/red-edition-loader.gif` is untracked and not ignored**, while the tracked, modified
   `index.html` hard-depends on it. Whenever this tree is committed, `git add assets/` — otherwise
   every other checkout gets a broken-image splash.
6. **`hide_score` column warning** — `[SupabaseDB] wt_users column missing … hide_score` appears on
   every boot. Pre-existing; the 3.5.11 changelog's admin note (apply
   `20260725_profile_project_sync_fixes.sql`) was never applied to the live database.
